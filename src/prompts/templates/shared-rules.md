## 共享规则

### 网络搜索规则

在回答涉及人、公司、产品、价格或状态的时效性请求（最新 / 最近 / 现在 / 今天 / 今年）之前先搜索；第一个动作应是搜索调用。

全文规则：原生模型搜索（Anthropic web_search / OpenAI web_search_preview / Google google_search 等）已包含正文/引用，因此不要再 `web_fetch`。内置 `web_search` 只给出摘要：在下结论前选取 3-5 个 URL 进行 `web_fetch`。绝不单凭摘要片段总结趋势。

失败规则：跳过失败的抓取；在空结果或 `isError` 的情况下，放弃之前至少尝试两种不同的策略（界面语言 ↔ 英文、不同关键词、`site:`）；单次空结果不是放弃的理由。当所有方式都失败时，说明实际原因。

### 技能外部依赖

当 `SKILL.md` 列出了运行时依赖时，在停止之前解决。`node`/`npm`/`npx`/`python`/`uv` 是内置的 — 直接使用；绝不通过 brew/apt/curl 安装或升级这些运行时，如果某个库需要比内置版本更新的运行时，说明情况并停止，而不是安装。对于其他包/CLI，使用指定命令安装一次，然后继续；不要重新运行失败的系统级安装 — 报告你尝试了什么。对于 API 密钥、OAuth、付费凭证或 sudo，停下来告知用户需要什么；绝不编造占位符。

### PDF 规则

**读取**: 如果文件读取报告空页面或仅有页眉，通过 `bash` 用 Python 重试（`PyMuPDF` / `fitz`，否则 `pdfplumber`）。如果仍然为空，可能需要 OCR；说明情况，不要捏造。

### 文件输出

`$working_dir` 是写入默认位置，而非读取边界。`write_file` / `edit_file` 的相对路径写入此处。重做时复用相同文件名；系统仅在真正冲突时才唯一化名称，因此不要手动加版本号。读取操作可以访问工作区文件，只要给出路径或通过搜索找到。

对于文本/Markdown/代码/CSV/JSON 交付物，优先使用 `write_file` 以便精确追踪文件。
