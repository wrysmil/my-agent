设计要点（v3.2 相对 v3.1 的关键差异）

  • 派发通知属于主 Agent 的"消息树"：挂载在主 Agent 紫色气泡下方，无独立头像（系统级通知），左缩进对齐气泡边缘
  • 主 Agent 状态机：思考 → 调工具 → 派发后切"等待 coder 回复"（灰色态）→ coder 完成 → 主 Agent 重新"生成中"（紫色脉冲）→ 写收尾文本
  • 派发通知是"系统通知"：无 actor 头像；内容是"已派发 coder · 等待回复 / 工作中 / 已完成"+ dispatch 步骤摘要
  • 派发通知内部挂子 Agent 实时步骤：thinking / tool_call / tool_result 列表（归属 coder，但视觉上挂在主 Agent 树下）
  • 子 Agent 回复气泡：coder 完成时新建，绿色实线头像 + "子 Agent 回复" + typewriter 文本
  • 手收差异：
    • dispatch_to：派发通知 + 回复气泡 + 主 Agent 后续收尾
    • hand_off_to：派发通知 + 回复气泡（标 "最终回答"），主 Agent 切"已完成"不再写收尾
    • run_worker：仅派发通知（无回复气泡，因为子 Agent 不输出可见文本）；完成后主 Agent 重新活跃
