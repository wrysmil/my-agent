优点：层级最清晰，主/子 Agent 归属一目了然；子 Agent 活动自动「收起」在 run_worker 下，主 trace 不臃肿。
代价：实现最重——需要后端带 actor 身份、前端新增嵌套容器；run_worker 结果与子 Agent 步骤分离展示。
方案 B · 平铺 + 徽章

所有步骤同层，子 Agent 步骤带徽章

write_file 直接平铺在主 trace 里，前面加绿色「coder」徽章标识归属。实现最简单，改动最小。

优点：改动最小、实现最快——只需给 worker 事件的 step 加一个「归属徽章」，渲染层几乎零重构。
代价：长 trace 时主/子 Agent 步骤混在一起，视觉层级弱；多个子 Agent 并行时易混乱。
方案 C · 独立 Agent 气泡

子 Agent 可见回复独立成气泡 + trace 徽章

dispatch_to / hand_off_to 的「可见回复」在 chat 流中独立成绿色 agent 气泡（含头像与名字）；trace 内步骤仍带徽章。run_worker 私密结果仍收在主 trace。

让 coder 子 Agent 写一个旅游主题 HTML 页面，并把结果直接给我看

优点：语义最贴切——dispatch_to/hand_off_to 的回复对用户可见，独立气泡最直观；用户能区分「谁说的」；hand_off_to 时该气泡即最终答案。
代价：需要前端新增 agent 消息类型；run_worker 私密结果仍建议配合 A 或 B 的徽章/嵌套展示。
