# Web 后端 HTTP API 手测清单（B6 / WU-07c）

> 覆盖 **19 REST + 1 SSE 流**，共 **44 条用例**（每条路由 ≥ 2 用例：至少 1 成功 + 1 失败）。
> 事实来源：`src/web/server/router.ts`（路由表）、`src/web/server/routes/*.ts`（handler）、
> `src/web/server/errors.ts`（`ApiErrorCode` / `ERROR_STATUS_MAP`）、`bin/my-agent-web.ts`（启动入口）。
>
> **注意**：本清单以**代码实现**为准。与 dispatch 描述存在的差异见 § 6「与 contract 草稿的偏离」。

## 1. 启动与前置

```bash
# 工作目录：仓库根
export MY_AGENT_HOME="$HOME/.my-agent"        # 数据根目录（providers.json / sessions/）
export DEEPSEEK_API_KEY="sk-xxxxxxxx"          # provider 真实调用（仅 SSE 流用例需要）
export MY_AGENT_WEB_PORT=4321                  # 默认 4321
export MY_AGENT_WEB_HOST=127.0.0.1             # 默认仅本机
export MY_AGENT_WEB_ROOT="$PWD/web"            # 静态资源根

npx tsx bin/my-agent-web.ts
# 期望日志：🌐 my-agent Web listening on http://127.0.0.1:4321
```

**鉴权**：**无 auth**。服务只监听 `127.0.0.1`，不做 token / cookie / session 校验。
因此所有 curl **不需要** `--cookie-jar`；下文模板保留该开关仅为将来引入 auth 时的占位。

**通用响应壳**：
- 成功：`{"ok":true,"data":<payload>}`
- 失败：`{"ok":false,"error":{"code":"<ApiErrorCode>","message":"..."}}`
- 每个响应都带 `X-Request-Id`（UUID）响应头，便于对日志。

**基础变量**（后续用例复用）：

```bash
BASE=http://127.0.0.1:4321
PID=deepseek-main          # 已存在的 provider id
MISSING=__nope__           # 不存在的 id
SID=<从 POST /api/sessions 返回的 session id>
```

### 6.1 SSE 手测

```bash
# C-1：保持连接，观察事件流（Ctrl-C 结束）
curl -sS -N -D /dev/stderr -X POST "$BASE/api/sessions/$SID/messages/stream" \
  -H 'Content-Type: application/json' \
  -H 'Accept: text/event-stream' \
  -d '{"text":"你好，简短自我介绍"}'
```

期望响应头 + 事件序列（12 种 event，见 `sse.ts` `SSE_EVENT_TYPES`）：

```
HTTP/1.1 200 OK
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
X-Stream-Id: 6f1c1c2e-...-...

event: message_start
data: {"id":"msg_...","role":"assistant"}

event: content_block_start
data: {"index":0,"content_block":{"type":"text"}}

event: content_block_delta
data: {"index":0,"delta":{"type":"text_delta","text":"你好"}}

event: content_block_stop
data: {"index":0}

event: message_delta
data: {"stop_reason":"end_turn","usage":{"output_tokens":42}}

event: message_stop
data: {"stop_reason":"end_turn"}

event: usage
data: {"usage":{"input_tokens":18,"output_tokens":42}}

event: done
data: {"ok":true,"streamId":"6f1c1c2e-..."}
```

断线重连去重：带 `-H 'Last-Event-ID: 12'` 重发，服务端从该序号之后续发。

工具调用时额外出现 `tool_use` / `tool_result`；运行期异常出现：

```
event: error
data: {"error":{"code":"CHAT_RUNNER_ERROR","message":"..."}}
```

abort 后出现：

```
event: aborted
data: {"streamId":"6f1c1c2e-..."}
```

## 8. 与 dispatch 草稿的偏离（重要）

| dispatch 描述 | 代码实际 | 处理 |
|---|---|---|
| `POST /api/providers/reorder` | **不存在**该路由 | 换成实际存在的 `PUT /api/providers/:id`（P-6/P-7） |
| `DELETE /api/providers/:id` → 200 | 200 `{deleted}` ✅ | 一致 |
| `DELETE /api/sessions/:id` → 200 / 404 | **204 No Content**，且不存在也 204（幂等） | 用例按 204 写（S-8/S-9） |
| `POST /api/providers` → 200 | **201 Created** | 用例按 201 写（P-3） |
| `POST /api/sessions` → 200 | **201 Created** | 用例按 201 写（S-3） |
| 失败码 `VALIDATION_FAILED` | `errors.ts` 枚举未含该 code，但 routes 层 `sendJsonError` 直接下发字符串 `VALIDATION_FAILED`（422） | 按实际下发值记录；建议后续把 `VALIDATION_FAILED` / `PROVIDER_ALREADY_EXISTS` / `STREAM_ALREADY_RUNNING` / `STREAM_NOT_FOUND` 补进 `ApiErrorCode` 枚举 |
| SSE 「13 event」 | `SSE_EVENT_TYPES` 实为 **12** 个 | 按 12 个记录 |

### 9.2 curl 模板

```bash
BASE=http://127.0.0.1:4321
JAR=/tmp/my-agent-cookies.txt      # 当前无 auth，占位备用

# GET（打印状态行 + body）
api_get()  { curl -sS -w '\n[status=%{http_code}]\n' --cookie-jar "$JAR" --cookie "$JAR" "$BASE$1"; }

# 带 body 的写请求
api_send() { curl -sS -w '\n[status=%{http_code}]\n' -X "$1" "$BASE$2" \
               -H 'Content-Type: application/json' \
               --cookie-jar "$JAR" --cookie "$JAR" -d "${3:-{\}}"; }

# SSE
api_sse()  { curl -sS -N -D /dev/stderr -X POST "$BASE$1" \
               -H 'Content-Type: application/json' -H 'Accept: text/event-stream' -d "$2"; }

# 用法
api_get  /api/providers
api_send POST /api/sessions '{"kind":"gconv"}'
api_sse  /api/sessions/$SID/messages/stream '{"text":"你好"}'
```

### 9.3 一键冒烟（只读部分）

```bash
for p in /healthz /api/providers /api/providers/active /api/sessions /api/agents /api/skills; do
  printf '%-28s -> %s\n' "$p" "$(curl -sS -o /dev/null -w '%{http_code}' "$BASE$p")"
done
```

期望：`/healthz 200`、`/api/providers 200`、`/api/sessions 200`、`/api/agents 200`、`/api/skills 200`；
`/api/providers/active` 视是否配置 active 为 `200` 或 `404`。
